# 常见问题

## 我关掉了一堆东西，新开会话还是很长？

先看面板顶部的「首轮注入」是不是真的降了。三个常见原因：

1. 你关的是**旧会话**看到的数；策略只对之后新建的会话生效。
2. 大头是 `AGENTS.md` 或工具 schema，而你没关到对应通道（打开那一行的内容抽屉能确认它到底有多大）。
3. 面板的 token 是估算（ASCII ÷ 4，其他 ÷ 1.6）；真实占用看输入框下方统计行。

## 为什么 `AGENTS.md` 不能关？

它由 `dsh-agent-instructions` 在 `agent/pre-step` 直接注入成一条 user 消息，0.2.2 没有公开的抑制入口。插件选择只读展示：告诉你哪些文件真的在加载路径上、哪些超过了单文件 64KB 上限、哪些在 `~/AGENTS.md` 这种不会被读的位置，并且**内容抽屉里能读到真正被注入的那份文本**。改名/删除是旧版的做法，已废弃——它会在多目录会话里改错文件。

## 内容抽屉会读什么？会不会外传？

只读三类来源，全部来自快照自己登记过的路径：

- 技能注册路径上的 `SKILL.md`（读不到时退回目录里真正注入的那一行，并注明是目录行）；
- 工作区规则探测到的 `AGENTS.md` / `CLAUDE.md` 文件；
- 系统提示词段落、运行时上下文、工具声明：这些本来就是装配结果或内存里的对象，不读盘。

请求里**不能指定任意路径**，接口只接受「通道 + 条目 id」。单次读取有 2 秒预算、256KB 上限（模型工具单条 32KB），UTF-8 安全截断。读到的东西只在这次请求内返回给当前页面，**不写文件、不落盘、不联网、不上传**；关掉抽屉就没了。

## 趋势里为什么有「未知」的数据（斜纹）？

趋势只合并两种诚实来源：本插件自己写下的 `stats.json` 行（实测），和从历史会话日志里定价出来的行（日志）。日志行只测得到首轮总量，没有五条通道的分解，所以 `channels` 报 `null`、柱子画成斜纹——不补 0，因为 0 是一个我们没测过的断言。历史更早的实测行同理（通道分解是 2.0.0 才开始写的）。

「已记录 N 个会话 / 本机共 M 个」是覆盖率：没测过、也没有回填到的会话不会画进趋势。回填在**后台**跑（每分钟最多一轮、每轮最多 8 个会话、单轮预算 6 秒），读取接口立即返回已有数据并带 `backfilling: true`，所以趋势会随着后台补齐慢慢变多，但打开页面不会被回填卡住。

## 事件（events）存在哪？会记录对话内容吗？

`$DSH_HOME/injection-manager/events.json`，追加式，最多 300 条，原子写（临时文件 + rename），重复的宿主事件靠去重键只记一次。记录的是**策略与元数据**：哪个套件被关、预设切换、导入、撤销、压缩/剪枝、新会话建立，以及每次的 net token 变化。

不记对话正文：`params` 只接受原始值（字符串截到 200 字符、最多 24 项，嵌套对象直接丢弃），会话文本没有入口能进这个文件。重启不丢，删掉文件即清空；上限到了自动丢最旧的。

## 健康检查说「没有发现问题」，但我明明觉得很大？

健康检查是确定性的 7 类 code：插件 / MCP 重套件（单套 ≥25% 或 ≥30k）、DSH 自带套件占比提示（只提示，不建议关闭）、描述截断、不可关项占比、窗口未知、从没保存过策略、空技能目录。它只报"能行动"的问题，不按直觉打分：宿主自带的工具族再大也不会被推荐关闭。

另外两个契约里的 code（`duplicate-skill`、`tool-name-collision`）**永远不会出现**：这版宿主在插件能看到之前就把重名解析掉了，凭空报一条就是撒谎。枚举保留着，等宿主能观察时再加。

检查项是同一份快照的纯函数：同一份数据刷新两次，结果逐字节一致（唯一的时间值是快照的生成时间）。

## 新面板为什么显示「需要 v2 宿主」？

面板通过 `/summary` 的 `apiVersion` 判断宿主能力。宿主还是 v1 时，新版洞察、内容透视、健康检查这些需要新接口的能力无法工作，所以显示一张可关掉的 gate 卡（当前版本 / 最低要求 / 知道了），而不是让 tab 静默消失。升级插件后自动出现；管理、设置和所有开关不受影响。

## 洞察页的会话卡为什么比宿主的会话列表少？

因为趋势和会话卡只画「本插件测过或从日志定价过」的会话，而不是宿主知道的所有会话。这是有意的：没测过的会话没有任何数字可画，画一个空列会让人以为它真的没有注入。页脚会写明「已记录 N 个 / 本机共 M 个」。

## 我关掉一套之后，洞察里的历史点会变吗？

不会。洞察里的每个点描述的是**那一次测量时**的首轮注入；策略只影响之后新建的会话（以及之后的新测量）。所以你会在趋势上看到关闭动作对应的下降台阶，而不是整条线被重算——这正是这个页面存在的意义。

## 关掉一个工具，模型还能调用它吗？

不能。`tools.restrict({ deny })` 同时影响 schema 展示、查找和执行，三者保持一致。恢复开关即可复原。

## 关掉一个技能和关掉 `skill` 工具有什么区别？

- 关单个技能：在会话作用域注册同名、不可调用的技能，目录里只剩别的技能，`skill` 工具还在。
- 关 `skill` 工具：整个技能目录消息都不再注入（`dsh-tool-skill` 检测到工具不可见就发空目录），但你就没法按需加载技能了。

## 会影响正在跑的会话吗？

不会。策略在 `agent/created` 应用；面板会标明「本会话是否按策略处理」。`resume` / `compact` 也不处理。

## 两个窗口同时改会打架吗？

不会互相覆盖：每个动作只提交一个条目/一组，服务端按动作改文件；另一个窗口在重新获得焦点时刷新。撤销栈是进程级的，最后一个动作会被撤销。

## 撤销能退多远？

内存里保留最近 20 次写策略前的状态，重启清空。撤销本身也会写文件（并记一条事件），但不进栈。

## 这些 HTTP 路由会不会被网页跨站调用？

不会裸奔。2.0.1 起，全部 15 条路由在入口先过宿主 DSH 自己的准入门（`ctx.connection.requestRejection`）：Host/Origin 不被信任、或请求没有宿主签发的浏览器/API 凭据时，直接返回 401/403，空 body，路由逻辑与文件读取都不执行。写操作本来还有一层同源 POST 校验（JSON content-type + `sec-fetch-site` + 匹配的 `Origin`）。宿主没有 `connection` 服务（旧版本或启动早期）时栅栏自动跳过，插件保持旧行为——不会因此把面板挡死。

## 数据存在哪？会上传吗？

四个地方：`policy.json`（开关）、`stats.json`（每会话测量与通道分解）、`events.json`（事件流）、插件行的 `config`；另有浏览器 localStorage 存两个纯界面偏好。没有网络请求，没有遥测，不上传策略或会话内容。

## 和 `dsh-context` 是什么关系？

`dsh-context` 看**历史**：每个请求的组成、演进、压缩事件、多 Agent、文件与命令。这个插件管**下一次注入**：首轮到底塞了什么、哪些能关、关掉后什么代价。两者可以同时装，互不修改对方；我们是控制面，它是只读回放。

## 卸载后会怎样？

策略、统计、事件文件留在 `$DSH_HOME/injection-manager/`，不会自动删除；已生效的会话在插件卸载时解除注册（注册都挂在插件/agent 作用域上）。想彻底清掉就删这个目录。
