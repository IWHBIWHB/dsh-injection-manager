# 常见问题

## 我关掉了一堆东西，新开会话还是很长？

先看面板顶部的「首轮注入」是不是真的降了。三个常见原因：

1. 你关的是**旧会话**看到的数；策略只对之后新建的会话生效。
2. 大头是 `AGENTS.md` 或工具 schema，而你没关到对应通道。
3. 面板的 token 是估算（ASCII ÷ 4，其他 ÷ 1.6）；真实占用看输入框下方统计行。

## 为什么 `AGENTS.md` 不能关？

它由 `dsh-agent-instructions` 在 `agent/pre-step` 直接注入成一条 user 消息，0.2.2 没有公开的抑制入口。插件选择只读展示：告诉你哪些文件真的在加载路径上、哪些超了预算、哪些在 `~/AGENTS.md` 这种不会被读的位置。改名/删除是旧版的做法，已废弃——它会在多目录会话里改错文件。

## 关掉一个工具，模型还能调用它吗？

不能。`tools.restrict({ deny })` 同时影响 schema 展示、查找和执行，三者保持一致。恢复开关即可复原。

## 关掉一个技能和关掉 `skill` 工具有什么区别？

- 关单个技能：在会话作用域注册同名、不可调用的技能，目录里只剩别的技能，`skill` 工具还在。
- 关 `skill` 工具：整个技能目录消息都不再注入（`dsh-tool-skill` 检测到工具不可见就发空目录），但你就没法按需加载技能了。

## 预算为什么设了却「到不了」？

因为必填上下文（当前目录、子智能体身份）和工作区规则不参与裁剪。它们本身就超过目标时，面板会直说「到不了」，而不是假装成功。

## 会影响正在跑的会话吗？

不会。策略在 `agent/created` 应用；面板会标明「本会话是否按策略处理」。`resume` / `compact` 也不处理。

## 两个窗口同时改会打架吗？

不会互相覆盖：每个动作只提交一个条目/一组，服务端按动作改文件；另一个窗口在重新获得焦点时刷新。撤销栈是进程级的，最后一个动作会被撤销。

## 撤销能退多远？

内存里保留最近 20 次写策略前的状态，重启清空。撤销本身也会写文件，但不进栈。

## 应用预算会叠加当前的手动开关吗？

不会。应用预算会按目标 token 重算四条通道，把当前单个条目的关闭/开启**替换掉**。所以面板在检测到已有手动关闭项时会先提示「当前有 N 项被手动关闭；应用建议会按预算重算，并覆盖这些选择。」如果只想保留手动结果，别点「应用这套建议」，直接调大预算即可。

## 数据存在哪？会上传吗？

`$DSH_HOME/injection-manager/policy.json`，加上插件行的 `config`。没有网络请求，没有遥测。

## 和 `dsh-context` 是什么关系？

`dsh-context` 看**历史**：每个请求的组成、演进、压缩事件、多 Agent。这个插件管**下一次注入**：首轮到底塞了什么、哪些能关、预算多少。两者可以同时装，互不修改对方。

## 卸载后会怎样？

策略文件留在 `$DSH_HOME/injection-manager/`，不会自动删除；已生效的会话在插件卸载时解除注册（注册都挂在插件/agent 作用域上）。想彻底清掉就删这个目录。
