## 2.3.2 更新（2026-11-22）

**总分仍 8.8 / 10。** 这一版来自本人试用后的一句差评：「斜杠菜单里的 inject 没用」。不加分，但把
「入口名不副实」这条补上：

- `/inject` 从宿主文本命令改成客户端 `commandUi` 弹层——带插件图标、可搜索，前四行是动作
  （打开面板 / 最小预设 / 全开 / 撤销），后面按 token 排序列出可动套件；点一行即写策略。
- 顺手修了同一次改动里的真 bug：弹层发给 `/action` 的是去掉通道前缀的短 key（`core`），路由按
  完整 group id（`tools:core`）匹配，点了等于没点。
- 五入口仍然成立，只是第 4 个入口的形态变了（`docs/ARCHITECTURE.md` 规则 5、`COMPATIBILITY.md`
  已注明它依赖客户端 `commandUi`，0.2.x 两代未单独验证）。
- 证据：0.2.2-rc.5 QA 探针 12/12（斜杠行带 SVG 图标、弹层动作/套件分组、点 `core` 后 `onCount`
  23→0、弹层关闭、0 console error）；225 测试 / 0 fail；自审 100/100；npm 2.3.2 + tag `v2.3.2`。

## 按优先级排的差距

1. **发布与收录**：2.3.0 已发 npm 与 GitHub Release（2026-11-20）；剩余动作是向官方精选目录提交
   条目（本轮已备好 `market-entry.yml`）。没有收录，前四层做得再好也不会被官方看见。
2. **真实用户反馈**：找 5 个装了 15+ 插件的人跑 `/inject` 与五个入口，收集失败/误解；尤其验证
   右侧栏在不同窗口宽度与多显示器下的表现。
3. **会话标签页的信息量**：目前只回答「带多少」，没有「哪些最值得关」的会话内结论；下一轮加一行
   「本会话最大的可关套件」并复用管理页的跳转。
4. **0.2.0 / 0.2.1 真机验证**：兼容性文档里这两档仍是「预期」，需要一台旧宿主或在 QA 里降级安装。
5. **客户端可维护性**：client.js 拆模块（宿主允许 client 目录多文件），并给 SessionView/SettingsCard
   补 DOM 级测试。
6. **性能回归门禁**：把 `/summary`、面板打开、五入口打开的耗时纳入 CI，超过基线 20% 直接失败。
